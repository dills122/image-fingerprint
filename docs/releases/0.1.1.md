# image-fingerprint 0.1.1

This release adds an opt-in preview of crop-aware matching for applications that need to compare a
full source image with a smaller crop. The stable BlockHash, PDQ, codec, decoder, and comparison APIs
are unchanged.

## At a glance

- **Release type:** stable patch with an explicitly experimental preview
- **Package:** [`image-fingerprint@0.1.1`](https://www.npmjs.com/package/image-fingerprint/v/0.1.1)
- **Node.js:** 22.14 or newer; Node 22 and 24 are verified in CI
- **Headline:** generate and compare Crop-Local fingerprints through the isolated
  `image-fingerprint/experimental/crop-local` entrypoint
- **Stable API impact:** none

## Install or upgrade

```sh
npm install image-fingerprint@0.1.1
```

With pnpm:

```sh
pnpm add image-fingerprint@0.1.1
```

No data migration is required when upgrading from `0.1.0`.

## What's changed

### Crop-aware matching preview

The new experimental subpath can:

- generate verbose or compact Crop-Local fingerprints from decoded RGBA8 pixels;
- compare a source fingerprint to a crop fingerprint with directional `match`, `no-match`, or
  `insufficient-evidence` results;
- losslessly pack, unpack, and validate fingerprints for transport; and
- run as pure TypeScript in CommonJS, ESM, Node.js, browsers, and module workers.

The compact representation preserves the exact fingerprint values and comparison decisions while
roughly halving median serialized size in the included procedural benchmark.

### Better validation and release confidence

This release also adds reproducible crop-matching benchmarks and strengthens the required CI and
CodeQL gates. The benchmark-only retrieval index and an MTG-specific fallback that missed its
holdout quality floor remain internal rather than being shipped as supported APIs.

## Examples

Decode images with the stable Node adapter, then deliberately opt into the experimental matcher:

```typescript
import { decodeImage } from 'image-fingerprint/node';
import {
  comparePackedCropLocalSourceToCrop,
  fingerprintCropLocalItemPacked,
} from 'image-fingerprint/experimental/crop-local';

const sourcePixels = await decodeImage('./source.jpg');
const cropPixels = await decodeImage('./crop.jpg');

const source = fingerprintCropLocalItemPacked(sourcePixels);
const crop = fingerprintCropLocalItemPacked(cropPixels);
const result = comparePackedCropLocalSourceToCrop(source, crop);

if (result.status === 'match') {
  console.log('The crop is visually consistent with the source image.');
} else if (result.status === 'insufficient-evidence') {
  console.log('There is not enough signal to make a decision.');
}
```

The comparison is directional: pass the full image first and the candidate crop second. Keep
`insufficient-evidence` separate from `no-match` in application policy.

## Breaking changes

**None.** Existing stable imports, fingerprint schemas, serialized values, decoder modes, and
comparison behavior are unchanged. No experimental symbol is re-exported from the root, Node,
browser, or core entrypoints.

## Experimental

Everything under `image-fingerprint/experimental/crop-local` is a preview. Function names, types,
fingerprint shapes, profile identifiers, defaults, thresholds, and encodings may change or be
removed in any release, including a patch release.

Treat experimental fingerprints as regenerable. If they are persisted during evaluation, store the
package version and experimental profile beside them. The measured policy is a starting point, not a
universal production threshold: calibrate it with representative application data before relying on
decisions.

The current evidence supports visual crop consistency, not product identity, exact item identity,
cryptographic integrity, or adversarial-security decisions. The retained independent holdout
reported 49.7% recall, 99.3% precision, and a 0.00346% represented false-positive rate on its
specific corpus; those figures should not be generalized to other datasets.

## Compatibility

- `blockhash-v1` and `pdq-v1` output and schema version 1 serialization are unchanged.
- The Node and browser adapters and the Node-only `image-hash-v7` decoder mode are unchanged.
- Existing stored stable fingerprints do not need to be recalculated.
- The experimental implementation is available from its dedicated package subpath in CommonJS,
  ESM, TypeScript, Node.js, modern browsers, and module workers.
